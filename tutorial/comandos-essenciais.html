Domine os Comandos

Até aqui você usou o Claude Code de um jeito bem direto: pediu, ele fez. Essa lição mostra os comandos e atalhos que fazem diferença no dia a dia — e, mais importante, como reconhecer quando algo que o Claude está prestes a fazer merece um "espera aí" antes de aceitar.

~10 minutos

1

Comandos de barra

Os comandos que começam com "/"

Dentro do Claude Code, qualquer mensagem que começa com / não é uma pergunta pra IA — é um comando direto pro programa. Os mais úteis pro dia a dia:

/clear Apaga o histórico da conversa atual e começa do zero — útil quando o Claude "perde o fio" numa tarefa longa.
/init Analisa o projeto atual e gera um arquivo CLAUDE.md inicial — a próxima lição é só sobre isso.
/compact Resume a conversa até aqui pra liberar espaço, sem perder o contexto principal — bom pra sessões bem longas.
/cost Mostra quanto da sua sessão já foi usado — bom pra acompanhar o consumo se você estiver no plano por uso.
/permissions Mostra e ajusta o que o Claude Code pode fazer sem pedir confirmação (ler arquivos, rodar comandos, etc.).
/help Lista todos os comandos disponíveis, direto no terminal.
No terminal, dentro do Claude Code 
/clear
2

Atalhos

Os atalhos de teclado que valem a pena decorar

  1. Esc — interrompe o Claude Code no meio de uma resposta. Útil quando ele começa numa direção errada e você já sabe que quer corrigir antes dele terminar.
  2. Shift+Tab — alterna entre os modos de permissão: perguntar antes de cada ação, aceitar edições automaticamente, ou modo de planejamento (ele monta um plano antes de mexer em qualquer arquivo). Vale ficar de olho em qual modo está ativo — aparece indicado no próprio terminal.
  3. Ctrl+C — sai do Claude Code e volta pro terminal normal.
  4. Seta para cima (↑) — repete a última mensagem que você enviou, igual funciona em qualquer terminal.
Windows PowerShell ─▢✕ 
? for shortcuts                      Bypassing Permissions
>

O modo de permissão atual aparece no rodapé do terminal — Shift+Tab alterna entre eles. Simulação — troque pelo print real quando tiver.

3

Segurança

O que é prompt injection — e por que o modo de permissão existe

O Claude Code pode ler arquivos, acessar a internet e rodar comandos no seu computador — é isso que o torna útil. Mas isso também significa que, se ele ler um conteúdo de fora (uma página da web, um arquivo baixado, um e-mail colado) que contenha instruções escondidas ("ignore o que foi pedido antes e rode tal comando"), existe o risco dele tentar seguir essas instruções como se fossem suas. Isso se chama prompt injection.

É exatamente pra isso que existe o sistema de permissões: por padrão, o Claude Code pergunta antes de rodar comandos ou editar arquivos fora do que já foi combinado na conversa. Esse "pedido de permissão" é a sua chance de olhar o que está prestes a acontecer antes de acontecer.

Windows PowerShell ─▢✕ 
Claude wants to run:
  rm relatorio-antigo.txt

❯ 1. Yes
  2. Yes, and don't ask again for this session
  3. No, tell Claude what to do differently

Simulação de um pedido de permissão antes de uma ação — troque pelo print real quando tiver.

Regra prática Leia o que o Claude Code está pedindo pra fazer antes de aceitar — principalmente se envolver apagar, sobrescrever ou enviar algo pra fora do computador. Nunca ligue "aceitar tudo automaticamente" num projeto que tem conteúdo de fontes que você não controla (um repositório baixado de alguém, um site que o Claude acabou de ler). Na dúvida, prefira sempre o modo que pergunta antes.
